# F3 – Mijiedarbību žurnāls

| Lauks | Vērtība |
| --- | --- |
| **ID** | F3 |
| **Prasības tips** | Funkcionālā |
| **Atkarības** | F0 (Login un reģistrācija), F1 (Organizācijas) |
| **Maršruti** | Lapa `/organizacijas/{id}` (organizācijas kartīte), API `/organizations/{id}/interactions`, `/interactions`, `/auth/me` |
| **Līgums** | `docs/openapi.yaml` · `GET/POST /organizations/{id}/interactions`, `GET /interactions`, `GET/PUT /interactions/{id}`, `GET /auth/me` |
| **Statuss** | Īstenošanā. Lēmumus šajā aprakstā pieņēma izstrādātājs (MI aģents), un analītiķim tie jāapstiprina. |

## 1. Mērķis

Darbinieks pieraksta katru saziņu ar organizāciju (zvanu, e-pastu, sanāksmi): kad tā notika, par ko bija runa un kāds ir nākamais solis. Organizācijas kartītē redzama visa saziņas hronoloģija, tāpēc kolēģis var turpināt darbu, nejautājot, kas noticis iepriekš. Žurnāla ieraksti ir datu avots vadības panelim (F9: "Pēdējās mijiedarbības", "Nākamie soļi").

## 2. Mijiedarbības lauki

| Lauks | API nosaukums | Obligāts | Noteikumi |
| --- | --- | --- | --- |
| Datums | `occurredOn` | Jā | Formātā `GGGG-MM-DD`; nedrīkst būt nākotnē (šodiena pēc Latvijas laika, Europe/Riga) |
| Veids | `type` | Jā | `CALL` (Zvans), `EMAIL` (E-pasts), `MEETING` (Sanāksme) |
| Kopsavilkums | `summary` | Jā | 1–2000 rakstzīmes pēc atstarpju noņemšanas sākumā un beigās |
| Nākamais solis | `nextStep` | Nē | Līdz 500 rakstzīmēm; tukša virkne = `null` |

Sistēma pati piešķir `id`, `organizationId` (no adreses), `authorId` (pieslēgtais lietotājs), `createdAt` un `updatedAt`. Atbildē ir arī `organizationName`, lai sarakstos nav jāielādē organizācija atsevišķi.

## 3. Darbības

- **Pievienot:** `POST /organizations/{id}/interactions` → 201. Neesošai organizācijai 404.
- **Organizācijas hronoloģija:** `GET /organizations/{id}/interactions` → visas organizācijas mijiedarbības, jaunākās augšā (pēc `occurredOn`, tad pēc pievienošanas secības).
- **Visu mijiedarbību saraksts:** `GET /interactions?mine=&limit=` → jaunākās augšā. `mine=true` atstāj tikai pieslēgtā lietotāja ierakstus; `limit` 1–100, noklusējums 50. (F9 bloks "Pēdējās mijiedarbības" izmanto `mine=true&limit=5`.)
- **Skatīt:** `GET /interactions/{id}`.
- **Labot:** `PUT /interactions/{id}` aizstāj visus laukus. Labot drīkst tikai ieraksta autors; citiem 403 `FORBIDDEN`. Organizāciju mainīt nevar.
- **Kas es esmu:** `GET /auth/me` → pieslēgtā lietotāja `id` un `email`. Lapa to izmanto, lai rādītu pogu "Labot" tikai pie saviem ierakstiem.

Visām darbībām vajag pieslēgšanos; bez tās 401 `UNAUTHORIZED`.

## 4. Organizācijas kartīte `/organizacijas/{id}`

- Nepieslēgts lietotājs tiek novirzīts uz `/login`.
- Organizāciju sarakstā (`/organizacijas`) nosaukums ir saite uz kartīti.
- Kartītē: organizācijas dati, forma "Jauna mijiedarbība" un hronoloģija ar virsrakstu "Mijiedarbību vēsture".
- Katrs hronoloģijas ieraksts: datums, veids tekstā (Zvans / E-pasts / Sanāksme), autora e-pasts nav rādīts (datu minimizācija), kopsavilkums, nākamais solis.
- Pie saviem ierakstiem poga "Labot", kas ielādē ierakstu formā.
- Tukšā stāvokļa teksts: "Ar šo organizāciju vēl nav reģistrētas mijiedarbības."
- Neesošai organizācijai: "Organizācija nav atrasta." un saite atpakaļ uz sarakstu.

## 5. Pieņemšanas kritēriji

| ID | Ievade / situācija | Sagaidāmais rezultāts |
| --- | --- | --- |
| F3-1 | `POST` ar derīgu datumu, veidu un kopsavilkumu | 201; `authorId` = pieslēgtais lietotājs, `organizationId` = organizācija no adreses, `organizationName` aizpildīts |
| F3-2 | `POST` bez `occurredOn`, `type` vai `summary` | 400 `VALIDATION_ERROR`, katram trūkstošajam laukam `REQUIRED` |
| F3-3 | `occurredOn` = `"14.10.2026"` vai `"2026-02-30"` | 400, `occurredOn` / `INVALID_FORMAT` |
| F3-4 | `occurredOn` = rītdiena | 400, `occurredOn` / `IN_FUTURE`; šodiena ir derīga |
| F3-5 | `type` = `"SMS"` | 400, `type` / `INVALID_FORMAT` |
| F3-6 | `summary` > 2000 vai `nextStep` > 500 rakstzīmes | 400, lauks / `TOO_LONG` |
| F3-7 | `POST` vai `GET` hronoloģijai neesošai organizācijai | 404 `NOT_FOUND` |
| F3-8 | Organizācijai ir vairākas mijiedarbības | Hronoloģijā tikai šīs organizācijas ieraksti, jaunākais datums augšā |
| F3-9 | `GET /interactions?mine=true&limit=5` | Ne vairāk kā 5 pieslēgtā lietotāja ieraksti, jaunākie augšā |
| F3-10 | Autors labo savu ierakstu ar `PUT` | 200; dati mainīti, `updatedAt` atjaunots, `organizationId` un `authorId` nemainās |
| F3-11 | Cits lietotājs labo svešu ierakstu | 403 `FORBIDDEN`; dati nemainās |
| F3-12 | `GET` vai `PUT` neesošai mijiedarbībai | 404 `NOT_FOUND` |
| F3-13 | Jebkurš pieprasījums bez sesijas | 401 `UNAUTHORIZED` |
| F3-14 | Kartīte `/organizacijas/{id}` bez sesijas / ar sesiju | Novirzīšana uz `/login` / 200 ar formu un hronoloģijas sadaļu |

## 6. Personas dati (N2)

Kopsavilkums un nākamais solis ir brīvs teksts, un tajā var nonākt personas dati (piemēram, sarunas biedra vārds). Lapā ir atgādinājums: "Nerakstiet personas kodus, veselības vai citus sensitīvus datus." Glabāšanas termiņš un piekļuves žurnāls ir N2 tvērumā.

## 7. Ārpus apjoma

- Saite uz konkrētu kontaktpersonu (F2) — pievienos, kad būs F2.
- MI kopsavilkums un nākamā soļa ieteikums (MI-1) un marķējums «Ģenerēts ar MI».
- Uzdevuma izveide no nākamā soļa (F5, F9).
- Mijiedarbību dzēšana un izmaiņu vēsture.
- Redzamības ierobežojumi pēc lomas – sk. [N3.md](N3.md): reģistrē organizācijas atbildīgais, darbinieks redz savu organizāciju mijiedarbības, vadītājs visas.
- Lapošana.
