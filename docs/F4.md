# F4 – Pieprasījumi no organizācijām

| Lauks | Vērtība |
| --- | --- |
| **ID** | F4 |
| **Prasības tips** | Funkcionālā |
| **Atkarības** | F0 (Login un reģistrācija), F1 (Organizācijas) |
| **Maršruti** | Lapa `/pieprasijumi`, API `/requests` |
| **Līgums** | `docs/openapi.yaml` · `GET/POST /requests`, `GET/PUT /requests/{id}` |
| **Statuss** | Īstenošanā. Lēmumus šajā aprakstā pieņēma izstrādātājs (MI aģents), un analītiķim tie jāapstiprina. |

## 1. Mērķis

Organizācijas iestādei sūta pieprasījumus (jautājumus, lūgumus, priekšlikumus), uz kuriem jāatbild līdz termiņam. Darbinieks reģistrē pieprasījumu, maina tā statusu un redz, kuri ir kavēti vai drīz jāatbild. Pieprasījumi ir datu avots vadības panelim (F9: rādītāji "Kavētie pieprasījumi", "Atvērtie pieprasījumi", bloks "Kavētie un tuvākie pieprasījumi", vadītāja komandas kopsavilkums).

## 2. Pieprasījuma lauki

| Lauks | API nosaukums | Obligāts | Noteikumi |
| --- | --- | --- | --- |
| Organizācija | `organizationId` | Jā (izveidojot) | Esošas organizācijas ID. Pēc izveides nemainās |
| Nosaukums | `title` | Jā | 1–200 rakstzīmes pēc atstarpju noņemšanas |
| Apraksts | `description` | Nē | Līdz 2000 rakstzīmēm; tukša virkne = `null` |
| Termiņš | `dueDate` | Jā | `GGGG-MM-DD`. Var būt arī pagātnē (reģistrē novēloti saņemtu pieprasījumu) |
| Statuss | `status` | Izveidojot nē (noklusējums `NEW`), labojot jā | `NEW` (Jauns), `IN_PROGRESS` (Darbā), `ANSWERED` (Atbildēts) |

Sistēma pati piešķir `id`, `createdAt`, `updatedAt` un aprēķina:

| Lauks | Aprēķins (F9 datu noteikumi) |
| --- | --- |
| `organizationName` | Organizācijas nosaukums |
| `overdue` | `status` ≠ `ANSWERED` un `dueDate` < šodien (Europe/Riga) |
| `overdueDays` | Cik dienas kavēts; 0, ja nav kavēts |

`overdue` un `overdueDays` netiek glabāti, tos aprēķina katrā pieprasījumā, tāpēc tie vienmēr atbilst šodienai.

## 3. Darbības

- **Reģistrēt:** `POST /requests` → 201.
- **Skatīt:** `GET /requests/{id}`.
- **Labot un mainīt statusu:** `PUT /requests/{id}` aizstāj `title`, `description`, `dueDate`, `status`. Labot drīkst jebkurš pieslēgts lietotājs (pieprasījums ir kopīgs darbs, ne personisks ieraksts). Statusu var mainīt jebkurā virzienā, arī atvērt atbildētu pieprasījumu no jauna.
- **Saraksts ar filtriem:** `GET /requests`, sakārtots pēc termiņa (agrākais augšā), tad pēc ID. Filtri apvienojas ar "un":

| Parametrs | Nozīme | F9 lietojums |
| --- | --- | --- |
| `status` | Viens vai vairāki statusi (`status=NEW&status=IN_PROGRESS`) | "Atvērtie pieprasījumi" |
| `overdue` | `true` – tikai kavētie; `false` – tikai nekavētie | "Kavētie pieprasījumi" |
| `dueWithinDays` | Neatbildētie ar termiņu ≤ šodien + N (ietver kavētos); 0–365 | "Kavētie un tuvākie" (`7`) |
| `mine` | `true` – tikai organizācijas, kurām pieslēgtais lietotājs ir atbildīgais (F1) | Darbinieka skats |
| `organizationId` | Tikai šīs organizācijas pieprasījumi | Organizācijas kartīte |

Visām darbībām vajag pieslēgšanos; bez tās 401 `UNAUTHORIZED`.

## 4. Lapas

**`/pieprasijumi`**
- Nepieslēgts lietotājs tiek novirzīts uz `/login`.
- Filtri: statuss (izvēles rūtiņas), "Tikai kavētie", "Tikai manas organizācijas". Filtrus var iestatīt arī adresē (piemēram, `/pieprasijumi?overdue=true&mine=true`), lai F9 kartītes varētu vest uz filtrētu sarakstu.
- Tabula ar `<caption>` un `<th scope="col">`: Organizācija (saite uz kartīti), Pieprasījums, Statuss, Termiņš, Darbība.
- Statuss tekstā (Jauns / Darbā / Atbildēts); kavētajiem papildus teksts "Kavēts, N d." (ne tikai krāsa).
- Forma reģistrēšanai un labošanai. Ja adresē ir `organizationId`, šī organizācija formā ir iepriekš izvēlēta.
- Tukšā stāvokļa teksts: "Nav atrasts neviens pieprasījums."

**Organizācijas kartīte `/organizacijas/{id}`** — sadaļa "Pieprasījumi" ar šīs organizācijas pieprasījumiem un saiti "Reģistrēt pieprasījumu", kas atver `/pieprasijumi?organizationId={id}`.

## 5. Pieņemšanas kritēriji

| ID | Ievade / situācija | Sagaidāmais rezultāts |
| --- | --- | --- |
| F4-1 | `POST` ar organizāciju, nosaukumu un termiņu | 201; `status` = `NEW`, `organizationName` aizpildīts |
| F4-2 | `POST` bez `organizationId`, `title` vai `dueDate` | 400 `VALIDATION_ERROR`, katram laukam `REQUIRED` |
| F4-3 | Neesoša organizācija | 400, `organizationId` / `NOT_FOUND` |
| F4-4 | `dueDate` = `"2026-02-30"`; `status` = `"DONE"` | 400, attiecīgi `dueDate` / `INVALID_FORMAT`, `status` / `INVALID_FORMAT` |
| F4-5 | `title` > 200 vai `description` > 2000 | 400, lauks / `TOO_LONG` |
| F4-6 | Termiņš vakar, statuss `NEW` vai `IN_PROGRESS` | `overdue` = `true`, `overdueDays` = 1 |
| F4-7 | Termiņš vakar, statuss `ANSWERED`; termiņš šodien | `overdue` = `false`, `overdueDays` = 0 |
| F4-8 | `PUT` ar jaunu statusu un termiņu | 200; dati mainīti, `updatedAt` atjaunots, `organizationId` nemainās |
| F4-9 | `PUT` bez `status` | 400, `status` / `REQUIRED` |
| F4-10 | `GET` vai `PUT` neesošam pieprasījumam | 404 `NOT_FOUND` |
| F4-11 | `GET /requests?status=NEW&status=IN_PROGRESS` | Tikai atvērtie, sakārtoti pēc termiņa |
| F4-12 | `GET /requests?overdue=true` | Tikai kavētie; skaits sakrīt ar `overdue` = `true` ierakstu skaitu pilnajā sarakstā |
| F4-13 | `GET /requests?dueWithinDays=7` | Neatbildētie ar termiņu līdz šodien + 7, ieskaitot kavētos; neietver atbildētos un vēlākus |
| F4-14 | `GET /requests?mine=true` | Tikai to organizāciju pieprasījumi, kurām pieslēgtais lietotājs ir atbildīgais |
| F4-15 | `GET /requests?organizationId=1` | Tikai organizācijas 1 pieprasījumi |
| F4-16 | Nederīgs filtrs (`status=DONE`, `dueWithinDays=-1`) | 400 `VALIDATION_ERROR` |
| F4-17 | Jebkurš pieprasījums bez sesijas | 401 `UNAUTHORIZED` |
| F4-18 | Lapa `/pieprasijumi` bez sesijas / ar sesiju | Novirzīšana uz `/login` / 200 ar filtriem, tabulu un formu |

## 6. Ārpus apjoma

- Atbildes teksta glabāšana un nosūtīšana organizācijai.
- Atbildīgā darbinieka piešķiršana pieprasījumam (šobrīd atbildīgais ir organizācijas atbildīgais, F1).
- Statusu pārejas noteikumi un statusu vēsture.
- Automātisks termiņa aprēķins (piemēram, 30 dienas no saņemšanas).
- Dzēšana, lapošana, pielikumi.
- Redzamības ierobežojumi pēc lomas (N3).

## 7. Atvērtie jautājumi

- Vai termiņu nosaka likums (piemēram, Iesniegumu likuma 1 mēnesis), un vai to jāaprēķina automātiski?
- Vai vajag statusu "Atteikts" vai "Pārsūtīts"?
- Vai pieprasījumam vajag savu atbildīgo darbinieku, kas atšķiras no organizācijas atbildīgā?
- Vai atbildētu pieprasījumu drīkst atvērt no jauna?
